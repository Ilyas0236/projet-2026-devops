Chat de groupe temps réel par équipe (sport + catégorie) en WebSocket/STOMP natif Spring Boot, JWT validé au CONNECT par le service lui-même, historique persisté et notifications in-app pour les membres hors ligne.

Sécurité du canal — le JWT au CONNECT, pas dans l'URL

  • Pas d'Authorization sur l'upgrade WebSocket (impossible depuis un navigateur) : le client transmet son JWT en en-tête natif STOMP du frame CONNECT.
  • TeamChatAuthInterceptor valide la signature jjwt lui-même avec JWT_SECRET — aucune confiance dans un header X-User-* falsifiable, la gateway n'a pas à laisser passer du non-authentifié.
  • Le principal immuable TeamChatPrincipal(userId, role) est attaché à la session ; l'adhésion au groupe est revérifiée à chaque envoi (défense en profondeur).
  • L'adhésion est déduite des fiches Player/Staff (jamais stockée) ; ADMIN bypass ; un joueur FOOTBALL/U19 ne peut pas écrire dans PRO.
  • Texte uniquement, 500 caractères max, contrôlé client ET serveur.

Lot backend — WebSocket STOMP + service chat

  • Endpoint SockJS /ws/team-chat exposé via la gateway (/ws/team-chat* bypass), proxifié nginx avec en-têtes Upgrade corrects (timeout 1 h).
  • Mappings : /app/chat/{SPORT}/{CAT}/send et /presence ; topic de diffusion /topic/chat/{sport}/{cat}.
  • TeamChatService : validation contenu, adhésion via fiches, résolution du nom d'expéditeur, persistance team_messages, historique 100 derniers messages, membres du groupe, notifications in-app aux membres hors ligne uniquement (best-effort).
  • Suivi présence par groupe (ConcurrentHashMap<groupe, Set<userId>>) — sert à n'envoyer des notifications qu'aux absents.

Lot frontend — composant chat Angular

  • <app-team-chat sportType category> intégré aux dashboards entraîneur et joueur.
  • TeamChatService Angular : connexion SockJS+STOMP (@stomp/stompjs v7), reconnexion auto, resubscription aux groupes déjà rejoints, état diffusé via connectionState$.
  • Bulles WhatsApp-like (rouge = moi, blanc = les autres), badge rôle staff, horodatage, indicateur de connexion OPEN/CONNECTING/CLOSED, compteur 500 chars.
  • Fallback REST si socket fermé ; polyfills sockjs (global/process) câblés dans angular.json/tsconfig.
  • 5 specs Karma dédiées : chargement historique, isMine, refus vide/trop-long, envoi STOMP en ligne (fakeAsync), filtrage des groupes étrangers.

Le bug de prod trouvé et corrigé — identité sur le chemin WS

L'E2E manuel a révélé qu'un SEND STOMP pourtant authentifié était rejeté avec « Identité introuvable dans le contexte de sécurité ». Cause : le service lit le ThreadLocal SportsUserContext, alimenté uniquement par le filtre HTTP — absent sur le chemin WebSocket.

# Avant correction (docker logs) AccessDeniedException: Identité introuvable dans le contexte de sécurité at com.wydad.digital.sports.service.TeamChatService.requireCurrentUserId # Correctif (TeamChatWsController.send) SportsUserContext.setCurrentUserId(me.userId()); SportsUserContext.setCurrentUserRole(me.role()); try { teamChatService.sendToGroup(...); } finally { SportsUserContext.clear(); // jamais de fuite vers le thread suivant }

Un test dédié reproduit le scénario (principal → ThreadLocal → clear en finally) : suite sports-service passée de 52 à 56 tests verts.
